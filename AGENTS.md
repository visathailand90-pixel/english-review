# Управление английскими приложениями

## Рабочее место и границы
Единственный клон — english-review, origin https://github.com/visathailand90-pixel/english-review.git, ветка main, Pages из корня. Соседние inbox, private, archive, reports, tasks — личные, вне Git. Не трогать другие проекты. Читать ../tasks/ и последний ../reports/ перед работой. Новые материалы читать в ../inbox; не отправлять их во внешние сервисы без разрешения. Не публиковать оригинальные транскрибации, записи, сканы, секреты, личные истории, контакты и черновики. В публичные данные включать только обезличенный учебный результат. Не создавать PAT; использовать gh auth status и существующую OAuth-авторизацию. Никогда не печатать секреты.

## Команда «Обнови английские приложения»
1. Инвентаризировать inbox, сверить с отчётами (путь и SHA256 обработанных файлов) и существующими темами. Не повторять уже обработанные материалы. При неоднозначности уточнить; не выдумывать содержание отсутствующей транскрибации. Аудио без доступной локальной расшифровки отметить как блокер.
2. Проверить origin, main, git status, fetch; при чистом дереве pull --ff-only. Сохранить резервный git bundle и изменяемые исходники в ../archive. Чужие изменения сохранять; конфликт не разрешать уничтожением данных. Запрещены force push, reset --hard, clean -fd.
3. Из транскрибации извлечь темы, лексику и подтверждённые ошибки. Создать обезличенный русский конспект, грамматические формулы, примеры EN→RU, произношение, упражнения узнавания/выбора/вставки/сборки/перевода с объяснениями «почему так». Придуманные примеры обозначать учебными. Для свободного перевода предусматривать ручную оценку и корректные альтернативы.
4. Источник уроков — lesson-data/*.json и lesson-data/index.json; структура нового урока по существующему JSON. Существующие ID, порядок упражнений и поля не перенумеровывать. Новый урок добавлять следующим свободным ID (10, 11, ...). Не дублировать тему без причины. Существующие уроки и упражнения не удалять.
5. Слова: PACKS в words/index.html; добавлять отдельную пачку со стабильным id, не менять старые id и индексы слов. Читалка: статическая база в reader/index.html; добавлять новые тексты и словари со стабильными ID. Тексты генерировать локально при выполнении задачи, без runtime window.claude и платных API. Если запрос только про слова или читалку, менять только соответствующий контент.
6. Сохранять ключ english-review:v4, структуру progress и drafts, старую историю, ошибки и доступ к уроку 03 / уровню l3. Сохранять также ключи читалки chitalka.* и пачек слов. GitHub не хранит прогресс: между браузерами переносить экспортом/импортом JSON. Не очищать localStorage. Без отдельной задачи не добавлять аналитику и внешнюю базу.
7. python tools/build.py собирает index.html из app-template.html и JSON, обновляет версию кеша. Интерфейс менять в шаблоне. Проверять python tools/test_apps.py, синтаксис всех скриптов, 10 исходных разделов плюс новые, desktop и 390px, упражнения, независимые EN/RU, 4 задания, 3 лишних слова, am/a.m., объяснения, отсутствие автоперехода, исчезновение ошибок после 2 верных ответов, старый прогресс, историю, экспорт/импорт и ссылки трёх приложений. При отсутствии зависимостей остановить публикацию и сообщить причину.
8. Публикация разрешена только по прямому запросу «обнови приложения»/«опубликуй». Использовать publish-english.ps1: по умолчанию проверка; -Publish запускает подтверждение; -Publish -Approved разрешён агенту только при уже явном поручении пользователя. Проверить каждый diff на приватные сведения и секреты, передать точный список -Files; никаких git add . и фоновых синхронизаций. Тесты обязательны. Не обходить неуспешный gate.
9. После push проверить Pages deployment именно этого commit и HTTP/содержимое всех трёх URL. Если старая версия — проверить кеш и sw.js. Не объявлять успех без проверки. Сохранить ../reports/YYYY-MM-DD.md: источники и SHA256 (локально), добавленные уроки/темы/число заданий, слов, текстов; проверки, commit, URL и ограничения. Исходники inbox не удалять; отмечать обработку в отчёте.
